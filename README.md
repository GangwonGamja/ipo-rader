# IPO Radar

국내 상장 예정 기업을 매주 자동으로 찾아 정리하는 한국어 대시보드입니다. 일정, 기업별 리서치 보고서, 시장 관심도, 공모가의 상대 수준을 한 화면에서 봅니다.
외부 라이브러리 없이 Python 3.11 이상 표준 라이브러리만 사용합니다.

## 서버로 운영하기 (권장)

로그인 보호와 주간 자동 갱신을 내장한 웹 서버로 실행합니다.

```bash
python -m ipo_radar hash-password 홍길동   # 계정 해시 생성 → .env 의 IPO_RADAR_USERS
docker compose up -d --build               # 또는 python -m ipo_radar serve-prod
```

설치 순서, 사내 서버·클라우드 선택, 계정 관리, 백업은 `docs/DEPLOY.md`를 참고하세요.

## 빠른 시작

```bash
python -m ipo_radar run              # 수집 → 분석 → 보고서 → 브리핑 → dashboard/index.html 생성
python -m ipo_radar serve --port 8000 # http://localhost:8000/index.html
python -m ipo_radar status           # 소스별 상태, 최근 실행, 다음 예약 시각
python -W ignore -m unittest -v tests.test_radar
```

`dashboard/index.html`은 데이터가 들어 있는 단일 파일이라 그대로 열거나 정적 호스팅에 올려도 됩니다.

## 지점용 대시보드 (한국투자증권 건대역지점)

`data/brand.json`이 있으면 `dashboard/branch.html`(로고·지점명 포함, 밝은 화면 고정)을 함께 만듭니다. 이 파일이 없으면 브랜드 없는 `index.html`만 만듭니다.
지점 PC에서 `branch.html`을 브라우저로 열어 씁니다. 엑셀·캘린더 내보내기, 인쇄, 상담 메모 기능을 쓸 수 있습니다.

- **이번 주(첫 화면)**: 월~일 주간 캘린더(◀▶로 주 이동)와 그 주 IPO 기업 카드(한 줄 사업 요약·일정·공모가·주관사)
- **기업 소개**: 기업 개요(한 줄 요약·비즈니스 모델 표) / 재무(연도별 손익·재무상태·회사 전망 표) / 공모·일정 / 심화 분석(가치평가·관심도·이력) 탭, 출처는 각주 번호로 표시
- **오늘 할 일**: 오늘 청약·마감, 내일 청약 시작, 공모가 확정 예정, 7일 내 청약, 환불·상장, 수요예측 일정과 당사 주관 종목
- **고객 안내문 복사**: 일정·공모가·주관사·참고 포인트·유의 사항과 투자 유의 문구가 들어간 글. 당사 주관 종목이면 이해관계 고지 문구가 자동으로 붙습니다.
- **증거금 계산기**: 공모가 × 주수 × 증거금률, 균등배정 최소 증거금, 비례 배정 예상 주수(가정 계산)
- **내보내기**: 공모주 목록 CSV(엑셀용), 일정 .ics(아웃룩·구글 캘린더). 주간 실행 때 `dashboard/ipo_list.csv`, `dashboard/ipo_calendar.ics` 파일도 함께 만듭니다.
- **상담 메모·관심종목**: 그 PC 브라우저에만 저장됩니다. 고객 개인정보는 입력하지 마세요.
- 고객에게 보내는 자료는 사내 준법감시 기준을 따르세요.

## 부서 공유 방법

- 가장 간단한 방법: `dashboard/branch.html`을 부서 공유 폴더에 두고, 각자 브라우저로 엽니다.
- 매주 자동 갱신: 주간 실행 PC나 서버에서 `data/brand.json`의 `output`을 공유 폴더 경로로 지정하면, 월요일 08:00 실행 때마다 공유 파일이 새로 덮어써집니다.
- 상담 메모와 관심종목은 각자 PC 브라우저에만 저장되며 공유되지 않습니다.

## 데이터 소스 상태 (2026-10-29 개발 환경 기준)

| 소스 | 용도 | 필요한 것 | 개발 환경 결과 |
|---|---|---|---|
| IPOSTOCK `ipo04.asp?str1=연&str2=월` | 후보 발견, 일정 | 네트워크 접근 | **차단**(이 세션 네트워크 정책) — 파서는 합성 픽스처로만 검증됨 |
| OpenDART (`list`, `estkRs`, `fnlttSinglAcntAll`) | 공식 확인, 정정·철회, 공모 조건, 재무 | `DART_API_KEY` (무료) | 키 없음 + 도메인 차단 |
| KRX Open API | 비교기업 시가총액 | `KRX_AUTH_KEY` | 키 없음 |
| KIND | 상장예정일 교차확인 | 공식 API 없음 | 자동 수집 안 함(구조 확인·이용 조건 검토 필요) |
| 네이버 검색 API (뉴스·블로그·카페) | 관심도 | `NAVER_CLIENT_ID/SECRET` | 키 없음 |
| Google 뉴스 RSS | 뉴스 보조 경로 | 없음 | 도메인 차단 |
| 네이버 종목토론방 | 커뮤니티 | 상장 후 종목코드 | 상장 전 기업은 해당 없음 |
| 네이버 데이터랩 검색어트렌드 | 개인 검색 관심 추이 | 네이버 키 + 데이터랩 권한 | 키 없음 |
| YouTube Data API v3 | 공모주 영상 수·조회·좋아요·댓글 | `YOUTUBE_API_KEY` | 키 없음 |
| Claude API (Anthropic) | 기업별 AI 요약·상담 문장, 주간 AI 브리핑 | `ANTHROPIC_API_KEY` | 키 없음 |
| 수요예측·청약 결과(공시·보도) | 기관 수요 강도 | 없음(DART 연결 시 자동) | 웹검색 요약으로 일부 반영 |

커뮤니티 게시판(디시인사이드 등)은 직접 수집하지 않습니다. 여론은 공식 API와 공시로만 파악합니다.

접근 제한은 우회하지 않습니다. 401/403/robots 금지는 재시도 없이 '차단'으로 기록합니다.

**현재 들어 있는 실데이터**: `data/seed/websearch_20261029.json`. 웹검색 결과(요약과 기사 링크)에서 가져온 13개 기업입니다. 원문을 직접 열람하지 못했기 때문에 모두 '웹검색 요약' 등급(데이터 신뢰도: 낮음)으로 표시합니다. IPOSTOCK·DART가 연결되면 높은 등급 소스가 값을 대체하고, 값이 서로 다르면 '출처 불일치'로 기록합니다.

**예시 데이터**: `[예시]`로 시작하는 5개 가상 기업(`ipo_radar/sample.py`)이 화면과 산식을 시연합니다. KPI와 브리핑에는 포함되지 않습니다. 운영에서는 `--no-sample`로 끕니다.

## 운영 설정

1. **네트워크**: 다음 호스트로 나가는 접속을 허용합니다. `www.ipostock.co.kr`, `opendart.fss.or.kr`, `dart.fss.or.kr`, `openapi.naver.com`, `data-dbg.krx.co.kr`, `news.google.com`
2. **키**: `.env.example`을 참고해 GitHub Secrets나 서버 `.env`에 넣습니다. 키를 커밋하지 마세요.
3. **파서 점검**: `python -m ipo_radar probe ipostock`. 인식 건수가 0이면 출력되는 HTML로 `collectors/ipostock.py`의 `_LABELED` 패턴을 조정합니다.
4. **스케줄** (셋 중 하나):
   - 웹 서버 내장 스케줄러(`serve-prod`, 권장): 꺼져 있다가 다시 켜지면 놓친 수집을 바로 실행
   - cron: `deploy/crontab.txt` (`CRON_TZ=Asia/Seoul`, `flock`으로 중복 실행 방지)
   - systemd: `deploy/ipo-radar.timer`, `deploy/ipo-radar.service`
   - 내장 데몬: `python -m ipo_radar daemon`
5. **재무·비교기업**: 상장 전 기업 재무는 DART 정기보고서 API에 없는 경우가 많습니다. 증권신고서의 요약재무와 비교기업 정보는 `data/manual_inputs/*.json`에 출처 URL과 기준일을 붙여 넣습니다(형식은 seed 파일과 같음, `source_type: "manual"`). 이 자료가 없으면 가치평가는 '판단 유보'로 남습니다.

## 주간 파이프라인

```
seed(웹검색·수동입력) → IPOSTOCK(현재 월~+90일의 모든 월) → DART 공시(신고서·정정·철회)
→ 재무 → 뉴스·커뮤니티 → 관심도·가치평가 → 보고서(바뀐 경우만 새 버전) → 주간 브리핑 → 대시보드
```

- **멱등성**: 기업은 고정 uid와 별칭(정규화 이름, `dart:고유번호`, `ipostock:번호`)으로 식별합니다. 값은 바뀐 경우에만 `changes`에 변경 전후를 남깁니다. 보고서는 내용 해시가 바뀔 때만 새 버전이 되고, 브리핑은 주(월요일)마다 한 건입니다.
- **실패 복구**: 요청 단위로 지수 백오프 재시도(2·4초)를 합니다. 한 실행 안에서 실패한 호스트는 다시 시도하지 않습니다. 단계가 실패해도 다음 단계는 기존 데이터로 계속하고, 전체 실패 시 `--recover`가 30분 간격으로 최대 3회 다시 실행합니다. `source_status`에는 마지막 성공 시각, 오류, 연속 실패 횟수를 남깁니다. 수집이 실패한 주에는 '목록 이탈(연기 가능성)'을 판정하지 않습니다.
- **탐지 항목**: 신규 발견, 일정 변경, 공모가 확정, 정정공시, 철회, IPOSTOCK 목록 이탈(연기·철회 가능성), 새 위험요인, 출처 불일치.

## 적정가 판정 (주관사 산정 근거 재검토)

국내 IPO 공모가는 보통 '비교기업 평균 배수 × 적용 이익 ÷ 상장 후 주식수 = 주당 평가가액'을 구한 뒤, 여기에 할인율을 적용해 정합니다.
IPO Radar는 기사·증권신고서에 공개된 이 근거(`valuation.underwriter`)를 가져와 다음 순서로 다시 계산합니다.

1. **확인 실적 기준 가치**: 주관사가 확인된 실적(LTM 등)을 썼으면 주관사 평가가액을 그대로 씁니다. 조정 이익이나 미래 추정 이익을 썼으면 확인된 실제 이익으로 다시 계산합니다.
2. **실효 할인율** = 1 − 공모가 ÷ 확인 실적 기준 가치
   - 30% 이상: 상대적 저평가 가능성
   - 15~30%: 적정 범위
   - 15% 미만: 상대적 고평가 가능성
   - 구간 경계는 `config.FAIR_DISCOUNT_LOW/HIGH`에서 바꿀 수 있습니다.
3. **예상 적정 공모가 범위** = 확인 실적 기준 가치 × (70%~85%)
4. **미래 추정 의존도** = 1 − 확인 실적 기준 가치 ÷ 주관사 평가가액. 적자 기업처럼 확인 실적으로 계산할 수 없으면 '판단 유보'로 둡니다. 대신 '공모가를 정당화하려면 회사 추정 이익을 몇 % 달성해야 하는가'와 '추정을 그대로 믿을 경우의 참고 판정'을 함께 보여 줍니다.
5. **배수 민감도**: 비교기업 배수를 ±20% 바꿨을 때 판정이 어떻게 달라지는지 보여 줍니다.

적용 이익의 기준(실적인지 추정인지)이 확인되지 않으면 '잠정' 판정으로 표시합니다.

## Claude AI 요약

`ANTHROPIC_API_KEY`가 있으면 수집이 끝날 때마다 기업별 AI 요약(한 줄 요약, 사업 설명, 주목할 점, 유의할 점, 공모가 판단 요약, 상담 문장, 부족한 자료)과 주간 AI 브리핑을 만듭니다.
- 모델: `claude-opus-5-5`, 구조화 출력(JSON 스키마). 안전 분류기 거절 시 서버 측 대체 모델로 재시도(`fallbacks: "default"`).
- 수집된 사실만 입력으로 주고, 문장마다 근거 키를 붙이게 합니다. AI 문장은 고객 안내 전에 원문으로 확인하세요.
- 입력 내용이 바뀐 기업만 다시 생성합니다(비용 절감). 한 번에 새로 만드는 기업 수 상한은 `IPO_RADAR_AI_MAX`(기본 20)입니다.
- 모델 변경: `IPO_RADAR_AI_MODEL=claude-haiku-5-5`(가장 저렴). 서버 재시작 직후 수집에서는 AI를 건너뜁니다(`IPO_RADAR_AI_ON_CATCHUP=1`로 변경). 정기 수집(월 08:00)과 관리자 '지금 갱신' 때 생성됩니다.

## 여론 파악 방식 (3갈래)

1. **기관 수요(수요예측·청약 결과)**: 기관 경쟁률 40%, 의무보유확약 30%, 밴드 상단 이상 가격 제시 비율 20%, 확정가 위치 10%로 0~100점 '기관 수요 강도'를 냅니다. 75점 이상은 강함, 50점 미만은 약함입니다. 일반청약 경쟁률과 증거금도 함께 표시합니다.
2. **개인 관심**
   - 네이버 데이터랩 검색 지수: 모든 요청에 기준어 '공모주'를 함께 넣어 기업 간 비교가 가능하게 맞춥니다.
   - 유튜브 공모주 영상 반응: 조회·좋아요·댓글이 관심도의 '참여도' 항목에 실제 값으로 들어갑니다.
3. **언론·커뮤니티 논조**: 네이버 뉴스·블로그·카페와 유튜브 글을 공모가·밸류, 수요예측·청약, 수급·물량, 실적·성장, 사업·기술, 업황·테마 6개 논점으로 분류합니다. 논점별 긍정·부정 비중과 대표 글을 보여 줍니다.

## 산식

- **관심도(0~100)**: 언급량 35%, 증가세 30%, 출처 다양성 20%, 참여도 15%. 채널별로 정규화합니다. 증가세는 `ln((최근7일+5)/(직전7일+5))`로 소표본 급증을 보정합니다. 같은 IPO 단계 기업끼리 비교하고(3곳 미만이면 전체와 비교), 수집하지 못한 구성요소는 0점 대신 '산출 불가'로 둡니다. 반영 가중치가 50% 미만이면 점수를 내지 않습니다. 감성은 별도로 표시하며, 주가 상승 확률이 아닙니다.
- **가치평가**: 분석용 비교기업 배수(PER, EV/EBITDA, EV/Sales, 금융업은 PBR)의 25/50/75 백분위로 보수·기준·낙관 시나리오를 계산합니다.
  - 적자면 PER을 쓰지 않고, 음수 배수와 재무기간·연결/별도 기준이 다른 비교기업은 제외합니다. 배수마다 유효 비교기업이 3곳 이상이어야 합니다.
  - 공모 후 주식수와 잠재 희석을 반영하고, EV는 공모 후 순차입금 `차입금 − (현금 + 신주 공모대금)`으로 지분가치로 환산합니다.
  - 회사 전망 실적은 0/20/40% 할인 민감도 표로만 보여줍니다.
  - 판정 규칙: 공모가가 보수 시나리오 미만이면 '상대적 저평가 가능성', 낙관 시나리오 초과면 '상대적 고평가 가능성', 그 사이면 '적정 범위'입니다. 자료가 부족하면 '판단 유보'입니다.
  - 상장일 수급(유통물량, 확약, 경쟁률)은 가치평가와 별도 항목입니다.

## 한계

- IPOSTOCK 파서는 실제 페이지로 검증하지 못했습니다(접속 차단).

- 투자 포인트와 위험은 확보한 근거로만 만듭니다. 근거가 부족하면 3개를 채우지 않습니다.
- 이 도구는 리서치 보조용이며 투자 권유가 아닙니다.
